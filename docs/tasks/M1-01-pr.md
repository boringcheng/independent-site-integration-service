## 正文

```markdown
## 背景

M1 的第一个垂直切片：让系统能注册一家 SHOPLINE 店铺。
`shops` 是领域根实体，后续的任务、作业、分片、Webhook 事件都挂在 `shop_id` 上，
所以先把这条最窄的链路跑通。

## 目标

- 新增 `shops` 表与 Alembic 初始迁移
- 提供 `create_shop` / `ensure_shop` 仓储接口
- 提供命令行入口 `scripts/create_shop.py`
- 覆盖正常、重复、非法平台三类测试

## 不做什么

- 不接真实 SHOPLINE API（凭证与 OAuth 留到 M3 之后）
- 不做任务队列（M1 的后续切片）
- 不做 HTTP API（M3）

## 设计决策

### 1. domain 唯一

同一店铺不能注册两次，靠数据库唯一索引 `uq_shops_domain` 保证。

为什么不在应用层"先查再插"：并发下两个请求都可能查到"没有"，
然后都执行插入。唯一索引是唯一可靠的兜底。

### 2. 重复注册：仓储抛错，服务层幂等

- `create_shop()`：冲突时抛 `ShopAlreadyExists`，如实反映事实；
- `ensure_shop()`：捕获冲突并返回已有记录，供 seed 脚本 / 回调重试使用。

把"数据层不变量"和"调用方策略"分开：
后台手动建店需要看到冲突，seed 脚本重跑不该失败。

### 3. platform：VARCHAR + CHECK + StrEnum

- 数据库：`VARCHAR(32)` + `CHECK (platform IN ('shopify', 'shopline'))`；
- Python：`StrEnum`，避免拼写错误，IDE 可补全；
- 不用 MySQL ENUM：新增平台要改列定义，锁表风险高、可移植性差。

CHECK 是最后一道防线：即使有人手工写 SQL 或绕过应用层校验，非法值也进不来。

## 改动

| 文件 | 说明 |
| --- | --- |
| `app/models/base.py` | `DeclarativeBase` |
| `app/models/shop.py` | `Shop` 模型 + 唯一约束 + CHECK 约束 |
| `alembic/env.py` / `alembic/versions/*` | 初始迁移（CHECK 手动补） |

- 回滚：`alembic downgrade base` 后 revert 本 PR；

## 检查点 1：`app/utils.py`

全项目统一时间来源：

```python
def utcnow() -> datetime: ...
```

要求：返回 **naive UTC**（`datetime.now(timezone.utc).replace(tzinfo=None)`）。
不要用 `datetime.utcnow()`——Python 3.12 起已弃用。

## 检查点 2：模型

两个文件：

```
app/models/base.py    # class Base(DeclarativeBase)
app/models/shop.py    # class Shop(Base)
app/models/__init__.py # 导出 Base、Shop
```

`Shop` 的关键点：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BigInteger` 自增主键 | 店铺 ID |
| `platform` | `String(32)`，非空 | shopify / shopline |
| `domain` | `String(255)`，非空 | 唯一 |
| `status` | `String(16)`，默认 `ACTIVE` | 预留停用状态 |
| `created_at` | `DateTime`，默认 `utcnow` | naive UTC |

`__table_args__` 里放三样东西：

```python
UniqueConstraint("domain", name="uq_shops_domain"),
CheckConstraint("platform IN ('shopify','shopline')", name="ck_shops_platform"),
{"mysql_charset": "utf8mb4", "mysql_collate": "utf8mb4_0900_ai_ci"},
```

注意最后那个 dict 必须放在元组末尾。

自检：`python -c "from app.models import Shop; print(Shop.__table__)"` 能打印出表定义。

## 检查点 3：Alembic

```powershell

```

要改三处：

1. `alembic.ini`：把 `sqlalchemy.url` 那行注释掉（连接串从配置读，不写死）；
2. `alembic/env.py`：

3. 生成迁移：

**生成后必须逐行审查**，重点看：

- 唯一索引有没有生成（`uq_shops_domain`）；
- CHECK 约束**大概率没有**（Alembic 默认不检测），要手动加：
  ```python
  op.create_check_constraint("ck_shops_platform", "shops", "platform IN ('shopify','shopline')")
  ```
- 表字符集有没有（没有就在 `create_table` 里加 `mysql_charset="utf8mb4"`）；
- `downgrade()` 里有没有 `drop_table`。

验证三连：

```powershell

alembic downgrade base
alembic upgrade head
```

## 检查点 4：仓储

`app/repositories/shops.py`，三个函数 + 一个异常：

```python
class ShopAlreadyExists(Exception): ...

def get_by_domain(session: Session, domain: str) -> Shop | None: ...
def create_shop(session: Session, platform: str, domain: str) -> Shop: ...
def ensure_shop(session: Session, platform: str, domain: str) -> tuple[Shop, bool]: ...
```

关键写法：

```python
try:
    with session.begin_nested():     # 保存点：冲突只回滚这一小段
        session.add(shop)
        session.flush()              # 立刻触发 INSERT，才能捕获冲突
except IntegrityError as exc:
    raise ShopAlreadyExists(domain) from exc
```

三条纪律：

- **不 commit**，事务归调用方；
- 不要裸 `except`，只捕 `IntegrityError`；
- `ensure_shop` 捕获后重新查一次，返回 `(shop, False)`。

自检：`ensure_shop` 连续调两次，第二次返回 `created=False`，且表里只有一行。

## 检查点 5：命令行

`scripts/create_shop.py`：

```
--platform  必填，只在 shopify / shopline 里选
--domain    必填
```

流程：建 Engine → 开 Session → `ensure_shop` → `commit` → 打印。

输出示例：

```
shop_id=1  platform=shopline  domain=demo.myshopline.com  status=ACTIVE  (created)
shop_id=1  platform=shopline  domain=demo.myshopline.com  status=ACTIVE  (exists)
```

## 检查点 6：测试

`tests/test_shops.py`，四个用例：

| 用例 | 断言 |
| --- | --- |
| 正常注册 | 返回 id，字段正确，表里 1 行 |
| 重复注册 | `create_shop` 抛 `ShopAlreadyExists`；`ensure_shop` 返回同一 id |
| 非法平台 | `platform="amazon"` 被拒（Python 校验或数据库 CHECK） |
| 并发（加分） | 两线程同时 `ensure_shop`，最终只有 1 行，两边拿到同一 id |

测试隔离：domain 加随机后缀，别依赖清表顺序。

```python
domain = f"demo-{uuid4().hex[:8]}.myshopline.com"
```
